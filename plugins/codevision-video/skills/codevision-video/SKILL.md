# 코드비전 사내 영상

예전에는 녹화 원본을 틀어 놓고 중간중간 멈추며 사람이 손짓으로 설명했다. 이 스킬은 그 설명을 영상 안에 넣는다. 멈출 곳에서 영상이 멈추고, 봐야 할 곳에 테두리가 뜨고, 내레이션과 자막이 이유까지 말해 준다. 그래서 영상만 보내도 설명이 끝난다.

요청자는 원본(또는 만들 내용)만 준다. 컷·배속·멈춤·블러·대본·장면 구성은 내가 원본을 보고 정해서 시안으로 보여 준다. 편집 경험이 없는 사람이 많으니 "어디를 어떻게 자를까요"를 묻지 않는다. 시안을 보고 "1분 15초쯤 이거" 식으로 고치게 한다.

도구는 **HyperFrames**(heygen-com/hyperframes, Apache-2.0)다. 장면을 HTML·CSS·GSAP 로 쓰고, CLI 가 그 페이지를 프레임 단위로 찍어 mp4 로 만든다. 장면을 코드(`build.py` 의 장면 표)로 관리하므로 "이 문장 바꿔 줘"는 문자열 한 줄 수정으로 끝난다. Remotion 은 직원 4명 이상 회사면 유료라 쓰지 않는다.

## 어떤 영상에 쓰나

| 용도 | 재료 | 주로 쓰는 장면 |
| --- | --- | --- |
| 설치·사용법 가이드 | PC 화면 녹화 | `clip`(배속·멈춤·강조) + `card` |
| 공정 설명(감독관·고객사·평가 기관) | 공정 카메라·휴대폰 영상, 검사 결과 이미지 | `clip`(멈추고 부품·판정 짚기) + `flow` |
| 제품·기능 소개 | 없음 또는 대시보드 캡처 | `title`·`flow`·`card`·`end` |
| 시연·교육 | 화면 녹화 + 설명 카드 | 위 장면 섞어서 |

## 고정 규칙

### 회사 톤
- 배경 `#F4F6FA`, 포인트 `#002387`(로고 네이비). 글자 `#0b1a3a`, 보조 글자 `#4a5670`, 선 `#d9dfeb`. 로고와 맞춘 조합이라 바꾸지 않는다. 어두운 배경은 쓰지 않는다.
- 폰트는 Pretendard(스타터 `assets/fonts/`). 코드·명령만 고정폭.
- 강조와 NG 는 주황 `#ff6b2c`, OK·완료는 초록 `#12a150`. 다른 색을 더하지 않는다.
- 읽어야 하는 글자는 28px 이상으로 쓴다. 메신저로 받아 휴대폰에서 보는 사람이 많다.
- 실제 영상은 흰 테두리 카드(`.frame`) 안에 비율 그대로(`contain`) 넣는다. `cover` 나 큰 radius 로 자르면 가장자리 글자와 테두리가 잘려 어색하다.

### 내레이션·자막
- 목소리는 edge-tts `ko-KR-SunHiNeural`, 속도 `+5%`.
- 자막은 토스 문체 해요체로 화면 아래 한 줄. 자막에는 영문 이름을 그대로 쓴다. `build.py` 가 두 줄을 경고하면 내레이션을 나눈다.
- **TTS 대본은 한글 발음으로 따로 쓴다.** 영문을 그대로 주면 "Platform"을 "플래트폼"처럼 읽는다. → [references/narration.md](references/narration.md)
- 동작만 말하고 끝내지 말고 **왜 그런지 한 문장**을 붙인다. 보는 사람이 다음에 혼자 판단할 수 있어야 한다.

### 장면 문법
- **멈춤 + 주황 강조**: 보는 사람이 놓치면 안 되는 순간이 있다. 틀리기 쉬운 선택, 불량이 잡힌 부품, 판정이 바뀌는 프레임 같은 곳이다. 거기서 영상을 멈추고 그 부분에 주황 코너 표시(검사 ROI 모양)를 띄운 뒤, 내레이션이 이유까지 말할 동안 붙잡아 둔다. 사람이 영상을 멈추고 손가락으로 짚던 일을 대신하는 장치다.
- **배속 칩**: 기다리는 구간은 배속으로 줄이고 오른쪽 위 칩에 "12배속 · 실제 1분 26초", "일시 정지"를 띄운다. 보는 사람이 실제 걸리는 시간을 알아야 한다.
- **녹화로 못 보여 주는 것은 HTML 장면으로**: 준비물, 내부 처리 단계, 시스템 구조, 녹화에 안 찍히는 화면은 카드·흐름도·모션으로 따로 만든다. 그룹별로 체크가 차오르는 단계 목록 예시는 [references/example-steps.html](references/example-steps.html)에 있다.
- 순서가 있는 영상은 왼쪽 위 칩(`3단계` + 한 줄 설명)으로 지금 어디인지 알려 준다. 문서가 따로 있으면 문서 단계와 1:1 로 맞춘다. 소개 영상은 칩 없이 간다.
- 마지막 장면은 요약 + 더 볼 문서(사내 Notion 등) 한 줄.

### 가릴 것
- 접속 ID·주소·계정·IP·비밀번호 입력 화면, 고객사가 공개를 원치 않는 정보(사람 얼굴, 도면, 생산 수치 등)는 블러.
- 오류·실패 화면이 설명 목적이 아니면 잘라 내거나 흐린다. 단색 박스로 덮지 않는다. 인코딩 실수처럼 보인다.
- 원본은 레포 밖에 두고 git 에 올리지 않는다.

## 작업 흐름

명령은 OS 에 맞춰 쓴다. Windows 에서는 `python3` 대신 `python` 이나 `py -3` 이 맞을 수 있다.

0. **환경 점검**: 처음 쓰는 PC 면 `python3 "${CLAUDE_SKILL_DIR}/scripts/check_env.py"` 를 돌린다. 빠진 도구가 있으면 출력된 설치 명령을 요청자에게 보여 주고, 동의를 받아 설치한다.
1. **프로젝트 만들기**: 레포 밖에 `<영상 폴더>/hf/<이름>/` 을 만들고 `${CLAUDE_SKILL_DIR}/assets/starter/` 의 내용을 통째로 복사한다. 원본은 `<영상 폴더>/raw/`, mp4 변환본은 `<영상 폴더>/mp4/` 에 둔다. `hf/` 에서 `npm i hyperframes@0.8.214` 를 한 번 실행한다.
2. **원본 훑기**: 원본을 30fps mp4 로 바꾸고 컷 시트(몇 초 간격 썸네일 격자)로 전체를 본다. 보여 줄 순간, 기다리는 구간, 가릴 것을 타임코드로 적는다. → [references/recording.md](references/recording.md)
3. **장면 표 짜기**: 장면마다 무엇을 보여 주고 무슨 말을 할지 표로 먼저 적는다. 목표 길이가 있으면 대본 mp3 부터 뽑아 길이를 재고 줄인다. edge-tts mp3 는 끝에 무음이 0.8초쯤 붙어서 눈대중보다 길어진다.
   - 공정명·문서 이름·수치처럼 모르는 사실은 지어내지 말고 요청자에게 묻는다. 시안에 임시로 넣었으면 그렇다고 알린다.
4. **자르기**: `cut.py` 의 `CLIPS` 에 조각(원본, 시작, 끝, 배속, 화면)을 적고 `python3 cut.py` 를 돌린다. 멈춤은 끝을 `None` 으로, 블러는 `("blur", x, y, w, h)` 로 적는다.
5. **내레이션**: `build.py` 의 `vo` 에 `(시작, 이름, 자막, 한글 발음 대본)` 을 적고 `python3 build.py vo` 를 돌린다. 대본을 바꾸면 그 mp3 를 지우고 다시 돌린다.
6. **조립·검사**: 프로젝트 폴더(`hf/<이름>/`)에서 `python3 build.py && npx hyperframes lint` 를 돌린다. 오류가 0 이면 된다. 다음 경고는 이 구조에서 늘 나온다.
   - `nested_structure_needs_subcomposition`
   - `timeline_track_too_dense`
   - `duplicate_media_discovery_risk`(로고가 두 번 들어가서)
7. **캡처 검수**: 고친 순간마다 `npx hyperframes snapshot --at 12.5,40 --no-end -o snap .` 로 찍어 직접 본다. 강조 표시가 대상 위에 있는지, 자막이 내용을 가리지 않는지, 가릴 것이 다 가려졌는지 확인한다.
8. **미리보기로 시안 확인**: 요청자는 HyperFrames Studio(브라우저 미리보기, 타임라인·재생·탐색)에서 시안을 본다.
   - `npx hyperframes preview --background` 로 띄우고, `preview --status` 와 로그에서 주소(`http://localhost:<포트>`)를 찾아 알려 준다.
   - 바뀐 장면의 시각을 같이 적는다.
   - 고칠 때마다 `python3 build.py` 만 다시 돌리면 열려 있는 화면에 반영된다.
   - 확인이 끝나면 `preview --stop` 으로 끈다.
9. **고치기**: 피드백을 받으면 장면 표와 컷 값만 고친다. `index.html` 은 생성물이라 직접 고치지 않는다.
10. **렌더**: 요청자가 됐다고 하면 `npx hyperframes render -o ../../<이름>.mp4 --video-frame-format png` 를 돌린다. 오래 걸리니 백그라운드로 돌린다. 메신저로 보낼 만큼 줄여야 하면 다음 명령을 쓴다.
    ```bash
    ffmpeg -i <이름>.mp4 -c:v libx264 -crf 26 -preset slow -c:a aac -b:a 128k -movflags +faststart <이름>-모바일.mp4
    ```

렌더가 Chrome·공유 라이브러리 문제로 실패하면 `npx hyperframes doctor` 로 원인을 찾는다. 그 출력의 whisper·Kokoro·MusicGen 항목은 쓰지 않으니 무시한다.

## 장면 종류 (`build.py`)

| kind | 쓰는 곳 | 필드 |
| --- | --- | --- |
| `title` | 첫 장면, 로고+제목 | `title`, `subtitle` |
| `card` | 준비물, 항목 정리, 녹화 없는 단계 | `kicker`, `heading`, `rows` |
| `clip` | 녹화 영상 | `src`, `step`, `label`, `speed`, `marks`, `rect`, `length` |
| `flow` | 흐름도(카드가 화살표로 이어지며 하나씩 켜짐) | `heading`, `nodes` = (아이콘, 이름, 설명, 켜지는 시각) |
| `sub` | 내레이션과 따로 도는 독립 모션 | `composition` (`compositions/<이름>.html`), `length` |
| `end` | 요약·참고 문서 | `heading`, `rows`, `more`, `mono`(명령이 아니면 False), `more_at` |

모든 장면에 `length`(초)가 필요하다. `clip` 만은 생략하면 클립 길이 + 0.3초가 된다.

- `speed` 와 `marks` 의 시각은 **자른 클립 기준**이다. 멈춤을 넣으면 뒤 시각이 다 밀린다. cut.py 조각 길이(구간 ÷ 배속, 멈춤 초)를 더해서 계산한다.
- `marks` 좌표는 클립 픽셀 기준 `(시작, 끝, x, y, w, h)` 이다. 화면 배치에 맞는 환산은 build.py 가 한다.
- `rect` 로 영상이 놓일 칸을 바꾼다. 좁고 긴 터미널 줄이나 세로 휴대폰 영상에 쓴다. 기본은 화면 중앙 1500x810 칸이다.
- 내레이션에 맞춰 움직여야 하는 모션은 `sub` 대신 `KINDS` 에 함수를 하나 더 만든다. 같은 타임라인이라 시각을 장면 표에서 바로 맞출 수 있다. `flow`·`clip` 이 그 예다.
- `flow` 아이콘은 `ICONS`(camera·ai·dashboard·nas, `verdict` 는 OK·NG 알약)에서 고른다. 필요하면 72x72 선 아이콘을 더한다.
